# Executable workflow design

Use this reference when translating an approved direct, code or graph path into executable steps.

## Decision method

Give each real step one state-to-result responsibility and choose trusted-code, model or human execution from its uncertainty and risk.

Use nodes for executable work and edges for conditions/outcomes; distinguish stores, routing functions and stage labels. Match implemented LangGraph figures to registered nodes and compiled routes; label proposed components.

Split solving, formatting or review only for observed quality, failure isolation, observability or checkpoint needs. A diagram does not require a graph framework or an added critic loop.
