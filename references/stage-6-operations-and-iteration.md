# Stage 6 — Operations and Iteration: Technique Reference

Technique guidance supported by public documentation and website sources. This file supports aspects 6.1–6.6 of `SKILL.md`.

## Scope and owner handoffs

| Aspect | Owns in Stage 6 | Consumes and hands off |
| --- | --- | --- |
| 6.1 | Feedback intake, triage, attribution and issue outcome tracking | Consume 6.4 alerts and existing trace/evaluation contracts; send cases to 4.1 and repairs to component owners. |
| 6.2 | Prompt/Skill content and activation-metadata upkeep, dependency checks and affected coverage | Consume canonical metrics/cases/graders and 6.4 signals; send tested component versions/evidence to 6.6. |
| 6.3 | Memory lifecycle operations, contamination response and lineage audit extension | Apply 2.4/2.6/2.9 policy through 3.5 stores; send signals to 6.4 and evidence to 6.6. |
| 6.4 | Production collection/sampling, alerts, drift comparisons and dashboards | Consume approved definitions and deployed limits; deliver signals to triage, component response and audit owners. |
| 6.5 | Dependency incident cutoff/probes/restoration, approved-version registry publication and discovery/index/rule maintenance | Apply approved call/handoff/recovery contracts and consume authored versions from 3.1/6.2; send unresolved cases to 6.1 and publication/routing versions to 6.6. |
| 6.6 | Recurring evidence adjudication, change review and release manifests | Consume obligations, capture/CI policy and component evidence; publish manifest links and reopen changed design decisions. |

## Bad-case reflow and iteration loop (6.1)

**Signal intake and review.** In the review-cadence decision, choose permitted direct-feedback channels and the alert/evidence inputs received from 6.4. Link candidates to existing trace and serving-version IDs under approved retention. Assign urgent queue/response targets and routine review cadence to business/domain and engineering owners. Review repeated requests, abandonment and negative clicks alongside verified task outcomes before attributing agent failure; record severity and disposition. Production metric collection and alert delivery are owned by 6.4. [AWS feedback control loops](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops02-bp04.html), [tracing](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops05-bp01.html), and [observability security](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentsec05.html) (Agentic AI Lens current), accessed 2026-09-30.

**Failure attribution.** Review the task outcome and available trace before choosing a fix. Check data quality or labels, retrieval evidence, prompt/model response, route, tool/integration, workflow state, policy decisions, and evaluation grader. A missing document, bad tool argument, stale state, or faulty grader calls for different repairs. The attribution guide maps symptom and evidence to component, owner, candidate remedy, and validation check. [Anthropic agent evaluations](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) (2026-01-09) and [AWS feedback control loops](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops02-bp04.html) (Agentic AI Lens current), accessed 2026-09-30.

**Versioned improvement loop.** Track accepted issue IDs through cause, repair owner, validation, release-manifest ID and observed outcome. Record reproducible input, expected outcome and reviewer evidence before submitting a production failure to the 4.1 case owner. A training example is conditional on selected model-level repair and the 2.8 data policy. The Mermaid loop shows urgent/routine intake and owner handoffs to evaluation, component maintenance, the 6.6 change record and monitored outcomes from 6.4. Compare before/after results with the agreed measures; release operation follows 5.6. [AWS feedback control loops](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops02-bp04.html) (Agentic AI Lens current), [Anthropic agent evaluations](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) (2026-01-09), and [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) (API current), accessed 2026-09-30.

## Skill and prompt maintenance (6.2)

**Success and maintenance surfaces.** Map each prompt or Skill surface to Stage 4 criteria/graders and 6.4 signals. Aspect 6.2 owns authored content and Skill name/description activation metadata, assigning review triggers, owners and regression checks to selection and execution surfaces. Check required files/packages/tools and step dependencies; send confirmed failures to 6.1. Hand reviewed approved artifact versions to 6.5 for publication, without giving the registry a second authoring responsibility. [Anthropic agent evaluations](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) (2026-01-09) and [OpenAI skill building](https://developers.openai.com/plugins/build/skills) (Plugins current), accessed 2026-09-30.

**Coverage-based regression.** Select versioned 4.1 case IDs for direct/indirect requests, incomplete or ambiguous requests, contextual business requests, negative non-trigger requests, unsupported actions and known failures. In the per-skill coverage list, record surface/category, expected activation/outcome reference and isolation/coexistence coverage. Submit missing input/fixture/expected-outcome cases to the canonical case owner. Coverage and risk determine the selection size. [OpenAI skill building](https://developers.openai.com/plugins/build/skills) (Plugins current) and [Claude enterprise Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise) (current), accessed 2026-09-30.

**Maintenance evidence handoff.** In the maintenance plan, choose prompt-behavior checks for prompt edits and trigger/instruction/isolation/coexistence checks for skill edits. Record baseline/candidate artifact versions, selected cases and outcome evidence. Submit those versions/checks to the 6.6 manifest and review process, using the 4.5 verdict and 5.6 recovery-action references. Component owners resolve unmet runtime/file dependencies and required-step failures before presenting the candidate evidence. [OpenAI prompting](https://developers.openai.com/api/docs/guides/prompting) (Responses API v1/current) and [Claude enterprise Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise) (current), accessed 2026-09-30.

## Memory governance (6.3)

**Retention and authorized access operations.** For each retained memory class, schedule the 2.4 retention/expiry policy, correction-request route and deletion jobs with named owners and completion checks. Raw events and derived records can need separate deletion: deleting an AgentCore event leaves its extracted long-term information. Verify the 2.6 trusted namespace/user/agent/tenant enforcement after identity or permission changes, retaining denied-access evidence. Record these operations in the memory operations plan. [AgentCore retention](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-create-a-memory-store.html), [event deletion](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/short-term-delete-event.html), and [namespace IAM controls](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-organization.html) (AgentCore current), accessed 2026-10-01.

**Write and retrieval control verification.** Specify sample/review triggers for approved 2.4 content policy and 2.6/2.9 authority, intent, provenance and harmful-content controls. Check excluded secrets, authorized sensitive input and consequential-fact provenance against retrieved-use evidence. Record verification evidence, risk-selected reviewer, owner, disposition and failed-control/contamination route in the operations plan, including denied-access evidence bindings. Unperformed initial checks have executable procedure, expected evidence and owner/run gate; operational checks record actual results. Policy changes return to their original owner. [Microsoft memory safety](https://learn.microsoft.com/en-us/security/zero-trust/sfi/manage-agentic-memory-safety) (updated 2026-06-03), accessed 2026-10-01.

**Growth, correction and recovery.** Schedule approved stored-memory pruning/consolidation with growth triggers and owners, then record retrieval checks after reduction using Stage 4 criteria. In the contamination-response plan, assign detection/containment owners, quarantine affected records, trace source-to-derived propagation, correct/delete both classes and verify restoration from policy-permitted history. Check authoritative source, scope and time when correcting stale facts. Snapshot restoration leaves external actions requiring their own recovery owner. Active-context compaction remains governed by 2.4. [AgentCore strategies](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/built-in-strategies.html) (current) and [Microsoft memory safety](https://learn.microsoft.com/en-us/security/zero-trust/sfi/manage-agentic-memory-safety) (updated 2026-06-03), accessed 2026-10-01.

**Memory lifecycle audit extension.** Extend the common 4.4 event schema with source/derived memory IDs, operation/reason, provenance, completion and post-reduction verification evidence. Cover creation, retrieval, update, deletion and consolidation under the approved access/retention policy. Record permitted-history references and deletion completion for raw and derived data. These are project audit fields to map to the selected vendor events. 6.6 reviews the resulting obligation evidence; it does not redefine the memory lineage extension. [Microsoft memory safety](https://learn.microsoft.com/en-us/security/zero-trust/sfi/manage-agentic-memory-safety) (updated 2026-06-03) and [AgentCore record streaming](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-record-streaming.html) (current), accessed 2026-10-01.

## Production monitoring and drift detection (6.4)

**Production metric mapping.** In the monitoring table, map each selected Stage 4 outcome, constraint, latency, token/tool and cost definition/evaluator to a production source/query, task/version segment, collection or sampling window and proxy limitation. Link multi-step work to end-to-end completion/duration and select streaming/batch observations consistent with approved objectives. Record unavailable observations and the evidence needed. Use the 5.6 billing-source/delay decision for cost-per-success collection and reconciliation views. [AWS workload success criteria](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentperf01-bp01.html) (Agentic AI Lens current) and [AgentCore telemetry](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) (current), accessed 2026-10-01.

**Diagnostics and drift.** Choose separate input-mix and behavior/quality comparators, representative baselines and comparison windows in the drift plan. Correlate deviations with the 6.6 manifest before sending investigation evidence to 6.1. Select available 4.4 retry, repeated-state, revision and recovery events for collection and outcome-linked views; these diagnostics need corroborating outcome evidence. Component owners choose remedies after attribution. [AWS behavior monitoring](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops05-bp02.html) (Agentic AI Lens current), accessed 2026-10-01.

**Ordinary alerts and delivery.** For ordinary level/constraint alerts, record the approved measure/limit reference, comparable baseline, collection window, trigger, severity, delivery destination and response-runbook owner. Include token/tool, cost and compliance signals where applicable. 6.1 owns issue triage, 6.5 owns incident response, and 6.6 owns labeled compliance evidence review/adjudication. The drift plan separately records distribution/behavior comparison triggers. [MLflow production monitoring](https://docs.databricks.com/aws/en/mlflow3/genai/eval-monitor/production-monitoring) (MLflow 3 Beta, updated 2026-09-15) and [AWS cost attribution](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentcost05.html) (Agentic AI Lens current), accessed 2026-10-01.

**Operational views.** For critical or long-running workflows, show outcomes, critical-path durations, in-flight work, relevant failure/recovery signals, serving changes and cost per completion. Link to trace detail and response runbooks; choose depth by business impact and incident history. [AWS workflow dashboards](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops05-bp05.html) (Agentic AI Lens current), accessed 2026-10-01.

## Degradation, routing maintenance, and failure handling (6.5)

**Dependency incident recovery.** Reference each dependency's 3.1 deadline/retry/replay/fallback contract and the 2.3 stop/handoff route. In the incident policy, choose alert activation, cutoff/health owner and scope across concurrent callers, suppression, recovery-probe cadence/expiry and restoration tests. Record permitted substitute, user notice and staffed incident owner. Confirm task validity and authority before activating an alternative; an undone operation remains incomplete. Release/pressure actions use the 5.6 playbook. [AWS tool recovery](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops04-bp03.html) and [operational recovery](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops07-bp01.html) (Agentic AI Lens current), accessed 2026-10-01.

**Provider incident control binding.** Bind the approved timeout/retry/defer/throttling and alternate-route contracts to the deployed client, SDK or gateway owner. Record provider-specific incident activation and recovery-probe evidence. Test restored or alternative route quality, state compatibility and data constraints, using direct clients or gateways according to the approved deployment. [Azure gateway choices](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/azure-openai-gateway-multi-backend) (current Foundry guidance), accessed 2026-10-01.

**Incident error-response mapping.** Use the reachable transient, model-correctable, user-resolvable, denied and ambiguous-effect classes from 3.1. Map their rule IDs to incident trigger/triage owner, approved recovery or handoff and outcome/restoration evidence. Denied calls follow their stop route and uncertain effects require reconciliation before retry. Record these operational bindings in the incident error-response table. [AWS failure classification](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentrel07-bp02.html) (Agentic AI Lens current) and [LangGraph failure design](https://docs.langchain.com/oss/python/langgraph/thinking-in-langgraph) (OSS Python current), accessed 2026-10-01.

**Routing maintenance.** Assign a registry publication/synchronization owner for approved tool-contract versions from 3.1 and approved Skill content/activation-metadata versions from 6.2. Maintain separate catalog/discovery-index/routing-rule versions and deployment health; changes to authored Skill metadata return to 6.2 and semantic tool-contract changes to 3.1. Reference the 2.1 discovery design, select regression cases and consume 6.4 selection/misroute/outcome/latency/cost signals, with recall only for retrieval discovery. Reviewed evidence can reopen the discovery design. [OpenAI tool search](https://developers.openai.com/api/docs/guides/tools-tool-search) (Responses API v1 and Agents API beta v1 current), accessed 2026-10-01.

**Rule maintenance evidence.** Assign deterministic routing/business-rule owners and choose affected regression checks and review triggers. Submit the existing rule artifact versions and test evidence to the 6.6 manifest/review process, reference the 4.5 verdict and use the tested 5.6 restoration action for confirmed regression. Reverting configuration leaves external effects requiring reconciliation. [AWS behavior versioning](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops02-bp03.html) (Agentic AI Lens current), accessed 2026-10-01.

**Handoff and worker recovery operations.** Bind the authorized 1.3 handoff context and 2.3 continuation to a staffed incident queue/rota, user notice, response deadline and unclaimed action. For selected worker agents, operate the approved task deadlines and liveness checks, reconciling durable outcomes before retry/reassignment. Activate a smaller-model or single-agent substitute only when the approved task and authority checks support it. [Copilot Studio handoff](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-hand-off) (updated 2026-08-03) and [AWS operational recovery](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops07-bp01.html) (current), accessed 2026-10-01.

**Maintenance deliverable.** Record publication/synchronization owner and approved artifact-version references, separate registry/index/rule versions, review/publication steps, discovery-method reference, selected cases, signals and misroute triggers. Link tested publication or routing changes to 6.6 manifest and 5.6 restoration action. Keep published capability versions aligned with deployed capabilities; hand content/activation-metadata edits to 6.2 and tool-contract edits to 3.1. [AWS capability registry](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentrel04-bp02.html) (Agentic AI Lens June 2026 revision/current), accessed 2026-10-01.

## Compliance audit and version regression (6.6)

**Protected evidence review.** Reference confirmed obligations/owners from 1.4 and the common 4.4 capture/protection schema, including the 6.3 memory extension where relevant. In the compliance review plan, choose evidence samples/cadence and reviewers to check completeness, attribution, tamper evidence, access and retention/deletion execution against the deployed 5.5 baseline. Record missing-evidence disposition and escalation. Raw prompt review uses only content permitted by the approved policy. [NIST governance](https://airc.nist.gov/airmf-resources/playbook/govern/) (AI RMF 1.0 Playbook current), [AWS secure audit](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentsec05-bp01.html) (Agentic AI Lens current), and [OpenTelemetry sensitive data](https://opentelemetry.io/docs/security/handling-sensitive-data/) (updated 2026-01-14), accessed 2026-10-01.

**Control review and adjudication.** Schedule scoped adversarial rechecks against confirmed controls and the 5.5 baseline at risk-based or material-change triggers. Choose labeled violation/intervention and missed-harm/false-block review samples, cadence and accountable adjudicator using Stage 4 metric definitions and 6.4 alerts. Record disposition and escalation under approved thresholds. Third-party audit follows confirmed obligations; changed applicability returns to the 1.4 owner. [AWS security validation](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentsec09-bp03.html) (current) and [Microsoft Content Safety transparency](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/content-safety/transparency-note) (updated 2026-02-27), accessed 2026-10-01.

**Regression execution and review.** Instantiate the approved 4.5 affected-CI/full-suite and risk-trigger policy with execution/review owners and evidence requirements. Include affected component checks selected by 6.2/6.5, record candidate and comparison versions and obtain the predeclared pass/fail/inconclusive verdict. Link its disposition to the 5.6 action table. The operational review schedule follows the approved CI policy; material decision changes also require the affected document approvals. [Microsoft evaluation checklist](https://learn.microsoft.com/en-us/agents/agent-evaluation/evaluation-checklist) (updated 2026-05-20), [AWS CI practice](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops06-bp01.html), and [change management](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops07-bp03.html) (Agentic AI Lens current), accessed 2026-10-01.

**Release manifest.** Choose an assembly owner and link existing independently versioned code, model snapshot, prompt/skill, tool/schema, policy/configuration and relevant data IDs with their dependencies. Map the manifest ID to evaluation evidence, deployed release and traffic cohorts; designate the tested recovery baseline and 5.6 recovery-action reference. Include the required baseline/previous-version comparison evidence for any selected fine-tuning change. Publish the manifest reference for 6.4 version correlation and 6.1 issue outcome tracking. [AWS behavior versions](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops02-bp03.html) (current) and [OpenAI API version guidance](https://developers.openai.com/api/reference/overview) (REST API v1 current), accessed 2026-10-01.

**Documentation changes.** When a change alters an approved decision, record affected documents and responsible reviewers, update those stage documents and obtain renewed approval before dependent work. Record implementation changes that preserve design decisions through the existing versioned change path and manifest evidence. [AWS change management](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops07-bp03.html) (Agentic AI Lens current), accessed 2026-10-01.
